--- common.py, build_topk (the actual selection logic; identical copy also lives in task_a_data_prep.py and produces the benchmark) ---
def build_topk(composite: np.ndarray, K: float, seed: int = TIE_BREAK_SEED):
    n = len(composite)
    k = int(np.floor(K * n))
    if k <= 0:
        return np.zeros(n, dtype=bool), dict(boundary_value=np.nan, n_tied=0, n_tied_selected=0)

    order = np.argsort(-composite, kind="mergesort")
    sorted_scores = composite[order]
    boundary_value = sorted_scores[k - 1]

    strictly_above = composite > boundary_value
    at_boundary = composite == boundary_value

    n_gt = int(strictly_above.sum())
    n_tied = int(at_boundary.sum())
    n_slots_from_tied = k - n_gt

    selected = strictly_above.copy()
    if n_slots_from_tied > 0:
        tied_idx = np.flatnonzero(at_boundary)
        rng = np.random.default_rng(seed)
        chosen = rng.choice(tied_idx, size=n_slots_from_tied, replace=False)
        selected[chosen] = True

    tie_info = dict(boundary_value=float(boundary_value), n_tied=n_tied,
                     n_tied_selected=n_slots_from_tied)
    return selected, tie_info

--- FINDINGS ---
1. Selection logic: `strictly_above = composite > boundary_value` selects everyone strictly above the cutoff; `n_slots_from_tied = k - n_gt` is the exact remaining quota; `rng.choice(tied_idx, size=n_slots_from_tied, replace=False)` fills that quota from the tied group WITHOUT REPLACEMENT. The output array `selected` always has exactly k = floor(K*n) True entries -- this is a STRICT quota rule.
2. Ties ARE broken, by `np.random.default_rng(seed).choice(...)` -- a uniform random draw without replacement over the tied indices at the boundary value.
3. A seed IS passed: `seed: int = TIE_BREAK_SEED`, and TIE_BREAK_SEED = 20190101 (common.py line 23). `topk_within_split` and every call site in modeling.py use this default, so the model's top-K uses the SAME seed as the benchmark.
4. It does NOT differ from the benchmark's selection logic. task_a_data_prep.py defines its own build_topk (lines 231-265) which is a byte-for-byte identical implementation (same sort, same `>` / `==` split, same rng.choice quota-fill). common.build_topk is a near-verbatim copy of that original, later imported by modeling.topk_within_split for the model side, and by task_a_data_prep.py's own successors for the benchmark side.

!!! CONTRADICTS THE TASK BACKGROUND !!! The background states the benchmark was "confirmed tie-inclusive (score >= cutoff, all ties admitted), producing excesses of +2/+3/+1 over floor(KN) at K=5/10/20%." That is NOT what this code does, on either side. `build_topk` never admits all ties: it computes `n_slots_from_tied = k - n_gt` and draws EXACTLY that many from the tied group, so the returned selection always has EXACTLY floor(K*N) True entries -- zero excess, by construction, for both the benchmark and the model. Task A's own log confirms this empirically: "Candidates selected overall = 12,387 (should equal 12,387)" at K=10% on the full analytic sample (N=123,879), not 12,387+2 or any other excess. If a tie-inclusive benchmark with observed excess counts exists, it did not come from this codebase's build_topk -- it must be a different computation the user ran separately (e.g., a raw `>=` count), or a mistaken premise. This is reported here rather than silently assumed, per the instruction to quote the actual code rather than paraphrase.
